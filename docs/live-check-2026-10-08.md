# session-panel: живая проверка 2026-10-08

Десктоп (Code tab), движок 2.1.288, auto mode. Проверялся установленный `session-panel@claude-mods` 0.1.0 (Folder-источник: `plugins/session-panel` этого репозитория). `claude plugin validate`: passed. `claude plugin test`: 122 pass, 0 fail. Панель сверялась с данными движка по 6 скриншотам.

## Что починить

1. **Строка `SubagentHandback` в логе — шум.**
   - Видно: перед каждой строкой `done` идёт `general-purpo… SubagentHandback ✓ 2.5s`.
   - Причина: в auto mode субагент сдаёт отчёт через инструмент `SubagentHandback`, а мод пишет его как обычный вызов.
   - Предложение: не логировать успешный `SubagentHandback`, как уже не логируются успешные `Agent` и `SendMessage` (`register.tsx`, около 372-377). Тест: успешный `SubagentHandback` у субагента не добавляет строку в лог.

2. **В строке `done` нет ответа (только в auto mode).**
   - Видно: `done · $0.046 ✓ 22.2s` вместо `done · $0.046 — first`.
   - Причина: при сдаче через `SubagentHandback` у `turn.complete` пустой `e.answer`, и `agentOutcome` отбрасывает часть `— ответ` (`register.tsx:84-87`).
   - Варианты: принять как есть или брать текст из входа вызова `SubagentHandback`. Форма этого входа в типах не описана: есть только `@internal` поля `handback` и `handbackReport` у результата `Agent` (`claude-code-tools/index.d.ts` установленной копии, 724-732). Поэтому второй вариант хрупкий. Решения пока нет.

3. **Узкая панель: в логе пропадает исход.**
   - Видно: при ширине панели около 297 px строки выглядят как `Bash sle…` и `done · $…`. Не видно ни `✓ 8.0s`, ни красного `✗`, ошибку выдаёт только красный `who`.
   - Причина: когда тексту остаётся меньше 8 ячеек, исход переезжает в конец текста (`view.tsx`, около 599-602 и 617), а текст режется с конца вместе с исходом.
   - **Решение пользователя:** в узком логе первой убирать колонку `who`. Исход остаётся в своей колонке, ошибку видно по красному исходу. Ожидаемый вид:
     ```
     12:48:56  TaskStop          ✓ 0.0s
     12:48:56  stopped            27.4s
     12:48:56  Bash sleep 120    ✗ 3.3s
     12:48:53  Bash sleep 20    ✓ 20.0s
     12:48:29  spawned · gener…
     ```
   - Открыто: с какого порога убирать `who` и что делать, если места мало даже без `who` (тогда хотя бы резать текст до того, как приклеивать исход, чтобы исход сохранился).

4. **Узкая панель: от описаний субагентов остаются 2–3 буквы.**
   - Видно: `St…`, `Re…`, `As…`, а `@general-purpo…` занимает все свои 15 ячеек (`view.tsx`, около 502-510).
   - Предложение: скрывать `@type`, когда описанию остаётся меньше ~12 ячеек. Пользователь это не решал.

5. **Мелочь: вызов, прерванный остановкой, показан ошибкой.**
   - Видно: `general-purpo… Bash sleep 120 ✗ 3.3s` красным, хотя сама остановка — тусклая строка `stopped 27.4s`.
   - Предложение: вызов, оборванный остановкой агента, показывать тусклым. Низкий приоритет.

## Проверено и работает

- Длительности: `sleep 2` → `2.0s`, `sleep 90` → `1m 30s`. Строки `done` совпадают с `duration_ms` движка (`22.2s` = 22212 ms, `1m 41s` = 101321 ms).
- Деньги: на всех скриншотах Total = Session + Subagents, а Subagents = сумме строк. Стоимость копится через resume ($0.046 → $0.055). Агент, убитый после первого шага, получил свою стоимость ($0.036).
- Resume через SendMessage: ровно одна строка `resumed`, строка держит ◐ все 90 s сна (не меньше двух тиков синхронизации). Гонки нет.
- Лог: маскировка (`echo token=•••`); ошибки (`exit 1` и Read несуществующего файла дают красные `✗` и `who`); подпись MCP `codebase-memory-mcp:index_status`; `spawned ·`; `stopped 4.5s` без отметки; `you` для промптов; `engine agent-message` для отчётов субагентов. Успешный `SendMessage` по id не логируется.
- `/session-panel`: «Session pane closed.» и «Session pane opened.». После повторного открытия содержимое и сворачивание сохраняются, панель продолжает обновляться.
- Сворачивание: шеврон сворачивает секцию, сводка остаётся в заголовке. Запись идёт в `~/.claude/plugins/store/session-panel_inline-fb64dc720a6f.json` (`"turn": true`). Установленная копия пишет в тот же файл, что и прежние dev-запуски.
- Turn stats: Steps = 8 для хода из 8 шагов. У одношагового хода нет Steps, Tool time 0.0s, Response = Whole turn. Skills 77 = числу скиллов в сессии. MCP: 2 (`codebase-memory-mcp`, `issue-hub`), встроенные серверы десктопа отфильтрованы.

## Не баги (для справки)

- Whole turn = вывод / Model time, а Response = последний текстовый шаг вместе с его TTFT. Поэтому Response бывает меньше Whole turn.
- Model time + Tool time может превышать Elapsed: инструмент работает, пока модель ещё дописывает следующий вызов. Tool time уже считается как объединение интервалов.
- Cost хода включает траты субагентов внутри хода (в первом ходе $0.819 при Session $0.749).
- Tool time включает ожидание разрешения: в auto mode `exit 1` занял 2.6s, MCP-вызов 4.4s.
- ~0.9s у Read/Grep/Glob дают пользовательский хук `cbm-code-discovery-gate` (PreToolUse Grep|Glob, PostToolUse Read), а не мод.
- У агента, убитого на первом запросе (через 4.5 s), остаётся `—`. Если движок всё же списал оборванный запрос, эта сумма попала в Session.
- `validate` предупреждает `gating hook without .catch` (tool.call, agent.spawn, session.compact, classic.CwdChanged). Риска нет: при сбое после `next` движок оставляет его результат (типы движка, раздел о сбое хука: «a hook that fails … is skipped … or its last `next` result stands»). Чтобы убрать предупреждение, можно добавить пустой `.catch(($, e, next) => next(e))`, но примет ли его валидатор, не проверено. Тестов на сбой в этих хуках нет.

## Не проверено

- Usage: аккаунт не отдаёт `rateLimits`, секция скрыта.
- Исход `denied`: в auto mode нет запросов разрешения.
- `/compact` (строка `compacted`, `—` у Context) и `/clear`.
- Сворачивание после перезапуска: в следующей сессии Turn stats должен открыться свёрнутым.
- Смена cwd/worktree, больше 8 субагентов (`+N more`), упавший субагент (`✗`), цвета Context от 80/95 %, терминал.
