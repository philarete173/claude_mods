## Что починить

### Безопасность и нагрузка git-чтений

1. **Clean/process-фильтры** из `.git/config` и `.gitattributes` репозитория выполняются при чтениях мода. Собственный `git status` Claude Code при старте делает то же, но мод делает это в каждом ходе и после каждого Edit/Write/Bash и добавляет два пути, которых у базового `git status` нет:
   - новые неотслеживаемые файлы: `diff --no-index` по каждому, до 50 (`register.tsx:276-286`); комментарий на `:260-261` («as in any `git status`») для них неверен;
   - сабмодули: у `status` и `diff HEAD` нет `--ignore-submodules` (`:252`, `:263`).
   - Предложения: `--ignore-submodules=dirty` для обоих; новые файлы с атрибутом `filter` пропускать (один `git check-attr -z --stdin filter`) или считать их строки без git.
2. **Нет бюджета времени на чтение.** Таймаут 5–10 s на вызов, но цикл по новым файлам идёт дальше после таймаута: в худшем случае одно чтение длится около 10 минут. Предложение: остановиться на первом сбое или задать срок на всё чтение.
3. **Обход больших деревьев.** `-uall` перекрывает пользовательскую `status.showUntrackedFiles=no`. Если корень сессии — не репозиторий, но лежит внутри другого (например, dotfiles в `$HOME`), `status` обходит весь `$HOME` до убийства через 10 s, и так в каждом ходе; `GIT_CEILING_DIRECTORIES` не задан. Устаревший индекс перехэшируется дважды за чтение и не чинится (`--no-optional-locks`).
4. **Не установлено:** может ли `session.start` плагина сработать до того, как принят диалог доверия к папке. Если может, фильтры выполнятся до согласия пользователя (высокий риск).
5. **Мелочи:**
   - имя ветки рисуется как есть: bidi-символы (U+202E) проходят, имя можно подменить на вид. Предложение: вырезать символы категории Cf;
   - комментарий на `:67-68` («git 2.44 and later») устарел: Ubuntu-сборка 2.43.0 уже понимает `GIT_NO_LAZY_FETCH`;
   - git-lfs clean при чтениях копирует изменённые новые LFS-файлы в `.git/lfs/objects` (вывод, git-lfs не установлен);
   - собственный `GIT_READ_ENV` (`:69`) дублирует то, что движок добавляет к любому git сам (проверено по бинарнику 2.1.294, не 2.1.288).

### Поведение

6. **Сворачивание по правилу «кто нажал последним».** Нажатие записывает всю карту из памяти своей сессии, загруженную один раз при старте (`register.tsx:185`). Нажатие в другой сессии с тем же файлом сбрасывает остальные секции к её виду. Предложение: при нажатии сливать с картой из store или хранить по ключу на секцию. Там же: ошибка записи в store глотается (около `:674`), а нажатие до загрузки при старте (на панели, открытой `session.attach`) начинается с пустой карты.
7. **Разные файлы store у одного мода.** Плагин, прочитанный из папки, — `session-panel@inline` (`session-panel_inline-fb64dc720a6f.json`), из кэша — `session-panel@claude-mods` (`session-panel_claude-mods-d64ba78f6023.json`). Сворачивание между ними не общее. Эта сессия читает `inline`.
8. **Project устаревает** после правок не через инструменты Claude (редактор, терминал, фоновый Bash после возврата вызова) до конца следующего хода. Предложение: перечитывать на каждом втором 30-секундном тике с тем же правилом ×4.
9. **Пределы строки изменений.** Больше 50 новых файлов: `+A` — нижняя оценка без пометки. Статус больше 4 MiB (например, неигнорируемый `node_modules`) убирает строку вместо числа.
10. **Задержанный auto mode отчёт показывается.** Текст из `SubagentHandback` попадает в `done`, даже если auto mode отчёт задержал или пометил (поле `handback` у результата `Agent`: `withheld` / `flagged`). Только показ и с маскировкой, но главный агент этот текст не получил.
11. **Узкий лог теряет подписи.** Уже ~39 ячеек тип агента не виден нигде, кроме обрезанной строки `spawned · type: …`. Строки промптов теряют `you` / `engine`: «Готово, скриншот сделан» и `agent-message` выглядят как обычные строки.
12. **`Tokens ↑` не включает запись в кэш.** После паузы кэш истёк, ход стоил $1.29–1.38 при `Cache 50%`, а `Tokens` показал `682 ↑` и `184 ↑`. Дорогую часть выдаёт только Cache.
13. **Сырой markdown в `done`:** `— **Verdict:**…`, `— **session-…`.
14. **Атрибуция при одновременных агентах приблизительная:** тот же haiku-тест стоил $0.100, пока параллельно работало ревью, и $0.046 в одиночку. Ограничение известно по спеке; стоит упомянуть в README.
15. Прерванный остановкой вызов всё ещё красный (п. 5 прошлого списка).
   - Сессия разработки отложила пункт: в `ToolCallResult` флаг `isError` объединяет ошибку, исключение и прерывание, а `isInterrupted` есть только в свойствах отрисовки (`ToolUse`, `ToolGroupCall`).
   - Но есть признак без угадывания по тексту: `next.signal` у хука. В типах движка 2.1.288 у `Next`: «Aborts when the call this dispatch belongs to is abandoned: the user interrupted, a hook above settled first, or this hook ran out of budget». Значит, в хуке `tool.call` после `await next(e)` условие `ran.isError && next.signal.aborted` означает брошенный вызов.
   - Две другие причины на практике не мешают: если хук выше ответил первым, цепочка уже ушла без этого хука, и тусклая строка безвредна; бюджет за время работы инструмента не кончается, потому что его часы стоят, пока идёт `next`.
   - Проверить до того, как опираться: (1) срабатывает ли сигнал у субагента, остановленного через `TaskStop`, а не только при прерывании главного агента; (2) успевает ли сигнал сработать к моменту, когда `next(e)` возвращает прерванный результат. Оба вопроса закрывает тест с агентом на `sleep 120`, остановленным через 20 s.

- Узкая панель: на ~355 px нет `who`, исход справа; на ~270 px нет `@type`, описания и исход видны, Project и Turn stats влезают.
